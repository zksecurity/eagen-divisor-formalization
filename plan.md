## Ordering and discipline

`P4.1 → P4.2 → P4.3 → P4.4` are independent of each other in content
but ordered by value; land each as its own commit with a green
`lake build Divisor Tests` and pins updated in the same commit.
`P4.5`–`P4.7` follow, cheapest-first within each file touched.
Statements may be re-expressed through the new named fragments
(P4.2), but no theorem loses generality and no hypothesis is added;
axiom closures stay pinned as at the baseline.

## Risks

| Risk | Where | Mitigation |
|---|---|---|
| The AccInv head feeds the live tail through a helper the name scan missed | P4.1 | Delete-and-build is the oracle: the build fails loudly; do the internal-closure computation first, not by eye |
| A "redundant" import is load-bearing for instance resolution order or notation scoping | P4.3 | Remove per-file and rebuild; revert any file that breaks — imports are per-file, so bisection is trivial |
| Restating headlines through `maAcceptSet` changes the textual statements users pattern-match on | P4.2 | Keep the unfolding lemmas `maAcceptSet_eq`/`mem_maAcceptSet` and update the README listings in the same commit |
| Heartbeat work balloons | P4.5 | Profile first, fix only clear hotspots, keep raises where honest |
